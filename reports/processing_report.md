# 软件与 AI 生态知识图谱处理报告

## 一、项目概述

本项目围绕“软件与 AI 生态”构建课程知识图谱，目标是在保证实体规模的基础上，形成清晰的三级层级结构，并对数据获取、规范化、去重、融合和质量控制过程留下可复现证据。

知识图谱采用三级结构：

- 一级类别：软件与 AI 生态。
- 二级类别：系统软件、应用软件、人工智能模型与应用、开发工具与框架。
- 三级实体：具体软件、模型、工具或框架名称。

## 二、数据来源

项目目前使用三类数据来源：

- Wikidata：作为基础实体来源，覆盖操作系统、编程语言、数据库、移动应用、软件框架等类别。
- 中文来源：补充国产软件和中文名称信息，用于增强 Wikidata 对中文软件生态的覆盖。
- 新闻、论文与技术报告样本：补充 2024-2025 年前沿 AI 相关实体。

## 三、Wikidata 批量抓取与规范化

Wikidata 抓取采用分批策略，避免单次请求过大，并将原始结果持久化在本地缓存目录，便于断点后重新规范化。

当前统计结果如下：

- 原始抓取记录：6069 条。
- 规范化前保留记录：5573 条。
- 全局去重后实体：5325 条。
- 删除重复记录：248 条。
- 丢弃记录：496 条。
- 非软件实体过滤：157 条。
- 泛化描述过滤：339 条。
- 丢弃率：8.17%。
- 过短简介占比：7.34%。

规范化阶段使用 QID 作为全局去重主键。对于同一实体出现在多个抓取目标中的情况，系统保留一份实体记录，并记录其跨目标来源。当前检测到跨类别重叠实体 19 条，其中跨大类重叠 8 条。

## 四、本体治理与层级去噪

Wikidata 的 `subclass of` 结构存在循环依赖、多父节点和逻辑冗余。项目通过层级治理脚本对原始分类边进行清理，确保最终结构能够稳定映射到课程要求的树状层级。

当前治理统计如下：

- 原始层级边：36 条。
- 去环后层级边：33 条。
- 最终树结构边：28 条。
- 删除循环边：3 条。
- 裁剪多父节点边：5 条。
- 人工规范化覆盖规则：5 条。

典型去环案例：

- `浏览器 -> 客户端软件 -> 浏览器` 构成循环，清理后保留浏览器在客户端软件路径下。
- `浏览器 -> 互联网应用 -> 浏览器` 构成循环，清理后避免同一节点重复回指。
- `即时通讯软件 -> 通信软件 -> 即时通讯软件` 构成循环，清理后保留通信软件作为上级类别。

典型单父节点归并案例：

- 数据库引擎统一归入数据库路径。
- 浏览器统一归入客户端软件路径。
- 视频编辑软件统一归入图像与视频处理路径。
- 智能体框架统一归入智能体工作流路径。
- 即时通讯软件统一归入通信软件路径。

对应产物：

- `outputs/figures/taxonomy_governance_report.json`
- `outputs/figures/taxonomy_tree.txt`

## 五、多源实体融合

中文增强阶段引入国产软件实体和中文描述，并通过别名表、标准化名称和来源字段完成实体对齐。

当前融合统计如下：

- 输入记录：33 条。
- 去重后记录：27 条。
- 删除重复记录：6 条。
- 多源融合实体：3 条。
- 质量控制后保留记录：27 条。

典型对齐案例：

- `WeChat` 与 `微信` 对齐，来源合并为 `Wikidata` 和 `Baidu Baike`。
- `WPS Office` 与 `WPS/金山办公` 对齐，保留中英文别名。
- `Windows 11` 在多个来源中出现，融合后保留单一实体节点。

对应产物：

- `configs/entity_aliases_zh_en.json`
- `data/interim/merged_entities.json`
- `outputs/figures/alignment_stats.json`

## 六、简介质量控制

简介质量控制模块用于筛选描述过短、过长、语言不统一、实体名缺失和语义过泛的条目，并将其压缩为统一格式的一句话简介。该模块只基于原始描述和已有分类信息进行处理，不新增原始来源之外的事实。

当前统计结果如下：

- 输入记录：5325 条。
- 质量控制候选记录：1742 条。
- 样本处理记录：100 条。
- 最大简介长度：30 个中文字符。

候选原因分布：

- 英文描述：1611 条。
- 描述过长：1248 条。
- 描述过短：390 条。
- QID 形式实体名：222 条。
- 泛化描述：33 条。
- 截断描述：1 条。

对应产物：

- `data/interim/description_qc_sample.json`
- `outputs/figures/description_qc_stats.json`

## 七、质量控制策略

项目在不同阶段设置了自动化质量控制规则：

- 身份校验：过滤缺失实体 ID 或名称的记录。
- 类别校验：过滤明显不属于软件生态的实体。
- 描述校验：过滤过短、过泛或无意义描述。
- 去重校验：基于 QID 和标准化名称进行重复实体合并。
- 来源保留：多源融合后保留 `source` 字段，保证实体来源可追溯。
- 层级校验：对分类边执行去环和单父节点约束。
